# Continue the centre-path model

Live page: https://acidfang.github.io/score-ledger-store/recursive-cubes/

## Current geometry boundary

Joe’s latest explanation describes centre-out fracturing and face-to-face cube stacks, replacing the earlier beachball rationale. This version preserves the prior near-even directional geometry as an explicitly provisional numerical approximation. It does not establish literal cube contact, a single rigid parent cube with 200 physical faces, or a resolved branch-frame/contact/roll relation. In particular, the retained tetrahedral N=4 arrangement is not face contact on one rigid parent cube. The immediate child-to-parent axis rule remains unchanged. Centre spacing is tied to the retained sizes by (parent size + child size)/2. Absolute lengths are unspecified; no independent free-distance parameter is introduced. The FIR state process and shared shell-path representation below are implemented independently of that unresolved geometry interpretation.

## Governing relation and current implementation

- A parent has N sphere segments and N children. One segment is the whole sphere, two are hemispheres; segment boundaries/tips meet at top and bottom. Child centres are dispersed as evenly as possible as a field around the parent, at equal distance from it. This is not a requirement that every pair of children have identical separation.
- The atomic-number interpretation is tentative. This does not establish physical element properties. The independent “Children per parent · N” control accepts N = 1…200. The same count and ordered local direction arrangement repeat at every centre. Complete displayed generations always contain all N children.
- Directions are precomputed once per N and reused through every recursive parent frame. One child uses +Y and two use ±Y as display conventions. Three use exact120° equal spacing on the XY great circle, with C1=+Y and C2/C3=(±√3/2,−1/2,0); this polar-plane/indexed orientation is an explicit display convention. Four retain tetrahedral symmetry; six retain the previous axial symmetry internally. Other counts use a deterministic Fibonacci-sphere distribution: y = 1 − 2(i+½)/N, longitude = iπ(3−√5). This is the chosen numerical approximation to even spreading, not a proof of optimal spacing or an exact derivation of segment boundaries.
- Spherical and radial guides are optional. There is no cube framework or extra point-sampling grid. Full spherical segment boundary surfaces remain unimplemented.
- Every centre is a ZERO POINT. The child-to-immediate-parent ZERO POINT line defines the local rotation axis, recursively. This does not mean all generations lie on one global line.
- A child's bottom, local −Y, faces its parent; local +Y points away. A parent's turn carries the complete child frame; the child also turns around its own local Y axis.
- Follow actual centre trajectories. The complete pattern also appears once at a finer scale within its primary centre. This inner instance is finite; infinite nesting is not rendered.
- Joe’s EI specification assigns AI only source-occurrence transcription. This page is an illustrative implementation of the stated geometric relations; it does not establish a complete EI implementation. Binary means relations between addressed things. No physical claim is made.

## Identity, additions and history

Children have stable ordinal addresses C1, C2, …, C200. Increasing N attaches the next identities and redistributes the retained siblings using the chosen even-spread approximation. It does not reset angles, simulation time, the actual camera view or input values. Newly exposed children use the current parent state and may lie outside the existing view until Fit is chosen. The same arrangement is shared at every generation.

Changing N, depth or field scale starts a new trajectory segment; no line joins across the geometry change. Earlier segments retain their original node/address mapping, sampled world positions and inner-instance scale. They are drawn separately with dashed lines. Never use a new topology's numeric BFS index to read an old sample array.

Removed or temporarily unrendered addresses retain their committed values and unsubmitted text drafts in separate address-keyed maps in the tab. Drafts restore on revisiting the address or rendering it again; submitting commits only the selected address. Drafts are never silently substituted for committed values. A selection outside the current view is retained logically, with a visible boundary notice and a rendered ancestor used for inspection. It restores when rendered again, unless the user explicitly selects another address. Values, drafts and history are not uploaded or persisted across reloads.

Current trajectory history is limited to six seconds and 24,000 stored centre positions. Earlier geometry segments have a separate 12,000-position budget; the oldest samples expire. This is finite in-memory retention, not an immutable source ledger. Reset motion explicitly clears current and archived path history but preserves entered values. Hiding paths does not delete them.

## Mathematical implementation

The `relation-engine` script uses row-major matrices with column vectors and separate scale. For parent centre C, rotation R, size s, child size c and unit direction n:

- child centre = C + R × n × (s+c)/2
- child rotation = R × directionBasis × localYRotation

All siblings therefore have equal parent radius. Direction bases are proper right-handed rotations mapping local +Y to the radial direction. The initial roll, radius/size convention and root Y axis are explicit display choices.

Each child adds a fixed RGB contribution keyed only by its stable child index. The same palette repeats at every generation and stays unchanged when N changes. Visible colour is the equal-weight average of the root contribution plus the complete ancestry of indexed contributions. The indexed contribution maps each segment/direction to its child origin, so descendants retain that segment contribution in their ancestry. Optional selected-branch emphasis brightens the selected address’s root-child branch and dims the other branches without removing any centre or path. The root stays visible; selecting root treats all branches equally. This changes stroke opacity/width only, not the inherited RGB contributions. The palette spans broad RGB hues without repeating a six-colour cycle or changing with N. Palette and mixing are display conventions, with no nanometre labels, wavelength calibration or physical claim.

The observer is separate from model motion and is excluded from all node counts. Default “Turn with parent” mode rotates the camera basis with the root parent. Its independent relative observer rate starts at 0°/s: zero means no observer turn relative to the parent, while the model root continues at its unchanged illustrative absolute rate. The existing root/local model rates remain independent advanced controls. No canonical rate coupling is introduced. World mode uses an external frame and suspends relative observer motion. Switching modes preserves the instantaneous world camera pose before adopting the new frame's future motion.

Every new trajectory sample and archive endpoint records its actual root angle alongside its unchanged world positions. Parent-mode history uses Ry(current root angle − sample root angle) × stored world position before projection by the co-rotating camera. This is equivalent to removing the sample-time root rotation, and therefore removes shared root turn from the path itself. World mode uses original world positions. The relative observer angle affects only the camera. Legacy samples without a root phase are omitted from parent-relative paths and explicitly remain world-only; never reconstruct an unknown phase. Archived inner paths retain their original fixed scale. The UI labels the active path frame.

A sparse, optional set of 96 deterministic world-fixed reference points is projected through the same current camera. These points receive no independent rotation and are not physical particles, model children or trajectory samples. Their apparent motion exposes observer rotation.

The `view-engine` script separates camera math. Wheel zoom anchors a ray-intersected sphere surface when its guide is visible, otherwise a nearby centre-depth plane or the selected centre's view plane. Pinch holds the same world anchor under the moving midpoint. Camera changes only reproject stored world trajectories. Camera extent and its free-view target (stored in observer-frame coordinates) are explicit display state, independent of topology bounds. The camera basis is rotated by root angle plus relative observer angle in parent mode; focus targets are already world coordinates and must not be rotated twice. Before a count, depth, scale or instance change, the current camera target and extent are captured; the instantaneous world view is preserved, including a previously focused target; that captured target is converted back into observer coordinates. Such a change releases automatic centre-following so that a removed or relocated selected centre cannot pull the camera. Focus explicitly attaches the view to the selected centre again; Fit explicitly recalculates the whole-model framing. Yaw, pitch, zoom and pixel pan remain unchanged during geometry changes.

The `relation-ui` script samples actual world positions every 1/15 simulation second. Root/local default rates, 12°/s and 24°/s, remain adjustable demonstration parameters. Model-rate changes preserve continuous history. Relative observer-rate changes affect no model transform or stored world sample. Hidden pages do not advance simulation time. Step advances 1/30 second.

The inner instance is one fixed affine scaled copy of the whole relation and its trajectories about root; it adds no independent turn. Scale is min(0.5, 0.38/max(R,0.76)), with R the sum of parent-to-child distances along the deepest displayed chain. This bound is constant during each geometry segment. Inner addresses start with `root::inner/`. Select the inner instance and Focus centre to inspect it.

## Retained whole, two display filters, and FIR transitions

The whole addressed relation is retained symbolically by its indexed directions, recursive address rule, producing relations and model inputs. This is not a claim that infinitely many numeric nodes are allocated. A chosen address can be resolved through its ancestor chain without expanding unrelated siblings.

Two independent display filters are exposed:

1. **Visible centres:** an addressed domain, first outward generation, and last outward generation. Zero means the domain centre. Generation one means its N children. Only the requested finite descendants and ancestors needed to produce them are materialized. Dependency-only ancestors/intermediate nodes are not drawn or counted as visible centres. The request is pre-counted; a request over 1,600 displayed centres across the active instances, or over 1,600 materialized dependencies, is rejected atomically with an explanation. No partial sibling group is silently applied. Filter-anchor addresses can extend to 64 indexed steps; a relative generation range is 0–8. Materialized selections can therefore reach 72 steps, and selection/pending-selection persistence supports those addresses.
2. **Motion shells:** actual direct-descendant trajectory curves of every visible non-root centre (or the root when it is the only visible centre). Shell paths add no descendant markers or topology nodes. A root with N=100 and one visible generation has 101 centre markers and 10,000 real descendant-address shell curves per displayed instance. Outward centre expansion is separate and only happens when requested.

The N-direction/radial-offset template is shared across equal-size parents. A shell vertex is exactly the actual descendant centre from the original transform equation: the recorded parent centre plus its recorded sample-time rotation applied to the retained radial offset. The complete stored parent rotation already includes local phase; no second local turn is added. Templates keep the geometry segment’s own N, ratio, parent addresses and sizes. A positive uniform scale and rigid reparenting transform preserve this generating relation and immediate axes at each sample; a time-varying ancestor can change the complete world trajectory. Missing historical rotations are never fabricated.

Every model change runs through FILTER (the retained addressed domain), ISOLATE (exact changed WAS→IS inputs), RECONSTRUCT (dependent grains only), and OBSERVE (actual output checks), then appends a linked receipt. Topology, root rotation, shared direction/local-turn products, centres, rotations and sampled history-frame conversions have distinct dependency keys. Unchanged camera/style redraws reuse model transforms. Local-only changes retain first-level centres; root turn, ratio and topology invalidate their actual dependents. Rate changes affect future phase integration without altering current geometry. Checks include finite addressed output, exact preflight counts, fixed root, parent-before-child order, equal parent radius and the immediate outward local axis.

The inspector shows the selected address, producing relation, changed inputs, observed checks and reuse counters. The latest 48 linked transition receipts are retained in memory. Continuous motion is summarized in one-second windows with captured phase/revision endpoints, unioned dependencies and summed actual work. Older receipts expire with an explicit count; this is not a complete immutable event ledger. Export is available on request by the page button. No external/private ledger is used or changed. Original source and previous sampled position/frame arrays are not rewritten.

Current centre history remains limited to six seconds and 24,000 stored centre samples; previous geometry retains up to 12,000. Each new sample now retains its actual rotation matrix as well as original world position and root phase. Changing the centre domain/range, N, ratio or instance configuration starts a separate segment. Newly manifested addresses begin at current model time and are never given retroactive trajectories. Earlier segments retain immutable address mappings and templates.

Shell drawing has a separate 240,000-vertex budget. All requested addressed curves remain represented; when dense, the drawing uses uniformly selected existing sample times and labels the count/range. If even two points per curve exceed the budget, it reports that boundary and draws no partial shell branch set. The full rules and retained samples are unchanged. N=100 is substantially heavier than N=4/6; storage/template reuse does not imply a whole-page speedup. Native-Canvas tests measure only the test environment, not browser/device frame rate.

The fixed-viewport canvas, collapsible controls, anchored zoom/pinch, parent/world observer frames, branch emphasis, value/draft retention and update guards remain. The rendering is finite; full EI semantics and literal cube-face contact remain outside this claim.

New current/tail/archive samples record localAngle as well as rootAngle and full materialized rotations. Legacy times lacking the necessary phase omit virtual carrier paths; current phase is never substituted into an older sample. Existing materialized carrier frames are used directly. Old geometry uses its own retained source parameters/template and appears only under the explicit inactive-history overlay.

Calculated construction paths have a separate phase-origin cache, using the same producing geometry, rates, sample-time frame construction and parent/world period rules as selected-child forecasts. CubePredictions.build accepts an optional curveSet while keeping its original default behavior. Camera-only changes reproject cached points. Geometry, rate and reset changes invalidate the appropriate cache; a hidden rate round-trip cannot revive an obsolete phase origin. Calculated construction frames are never appended as observations.

The separate construction forecast is limited to320,000 projected curve vertices and120,000 node frames, with the existing conservative phase sampling bound. Observed construction projection has a240,000-vertex budget; existing sample times are uniformly thinned and the limit is stated. An inadmissible minimum request is rejected as a whole. Point/frame caches reuse each immutable sample/scope and do not silently materialize another N-ary generation. Parent-relative paths remove each sample's own root turn. Whole/inner instance scaling follows the original fixed affine rule.

The optional experiment can be inspected through “Cube construction centres + paths” beside the child-count controls. It stays off by default because the interpretation is not asserted as the complete confirmed model.
